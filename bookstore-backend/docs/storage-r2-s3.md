# R2/S3 File Storage Runtime Notes

This project uses browser direct upload through backend-issued presigned PUT URLs.

## Presign Upload Contract

`POST /api/files/presign-upload` returns:

```json
{
  "fileAssetId": "uuid",
  "uploadUrl": "https://...",
  "method": "PUT",
  "headers": {
    "Content-Type": "image/jpeg"
  },
  "expiresAt": "2026-06-25T00:10:00Z",
  "storageKey": "public/users/{userId}/avatar/{uuid}.jpg"
}
```

The website must send the exact `method` and `headers` returned by the backend when calling `fetch(uploadUrl, ...)`. Do not add an application `Authorization` header to the R2/S3 PUT request; auth is already encoded in the signed URL.

## Required Bucket CORS

Configure the R2/S3 bucket CORS to allow the website origin to upload and read browser-visible response headers. Replace the production origin before deployment.

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:5173",
      "http://127.0.0.1:5173",
      "https://your-storefront-domain.example"
    ],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["Content-Type", "x-amz-*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

For Cloudflare R2, the same intent applies in the dashboard CORS editor: allow `PUT`, `GET`, `HEAD`; allow `Content-Type` and `x-amz-*`; expose `ETag`; include every frontend origin that can call presigned URLs.

## Security Expectations

- `BOOK_IMAGE`, `AUTHOR_AVATAR`, `EBOOK_FILE`, `SAMPLE_FILE`, and `INVOICE` presign requests require an admin JWT.
- `USER_AVATAR` presign requests are requester-scoped; backend generates keys under `public/users/{requesterId}/avatar/...`.
- Backend validates declared content type and size before issuing a signed URL.
- Object keys are generated by the backend. The client only sends original file name, content type, size, purpose, and optional business IDs.
- Private assets must have `publicUrl = null`. User read/download access goes through `GET /api/digital-library/me/assets/{digitalAssetId}/read-url` or `/download-url`.
- Signed download expiry is controlled by `app.storage.presign-download-expire-minutes` and defaults to 5 minutes.

## Orphan/PENDING Uploads

If the browser PUT succeeds but `POST /api/files/complete-upload` is never called, the row remains `PENDING`. Current runtime behavior:

- `FileAssetPolicyService.requireActiveAsset(...)` rejects `PENDING`, so pending files cannot become active book images, avatars, ebook files, or sample files.
- `complete-upload` checks object existence before switching the row to `ACTIVE`.

Operational TODO: add a scheduled cleanup job or admin maintenance command to delete stale `PENDING` rows and their storage objects after a safe retention window, for example 24 hours. Until then, monitor `file_assets.status = 'PENDING'` and clean manually when needed.
